    Decision Policy

    Fixed rules validate the agents’ recommendation before Argo can act.

    • At least 30 requests per revision and fresh evidence (120-second expiry).
    • Hold when required evidence is missing or limitations remain unresolved.
    • Enforce error and latency safety limits before GO.
    • NO-GO for canary attempts above 2 AND more than twice stable, corroborated by a sampled canary request and matching log.
    • Production promotion requires human approval (HITL).

    Human approval rechecks these rules; it cannot override missing or stale evidence or hard safety limits.

    Decision Policy
    Implemented as deterministic Java/Quarkus rules in DecisionPolicy.java. Requires 30 requests per revision and fresh evidence; withholds GO for missing evidence or unresolved limitations; enforces error and latency limits; and requires eligible Production promotions to receive human approval. Approval cannot override these safeguards.
    04 / Missing evidence: where automation must stop
    Enterprise context: HTTP metrics stay green during a collector outage, telemetry misconfiguration, or evidence-access problem. Required dependency observations are unavailable, so the platform cannot justify promotion.
    Show: use a healthy v2 candidate at an active gate with no slowdown, at least 30 requests per cohort, and Development / no approval. Select Extended → Missing evidence and investigate. In Evidence explorer, compare healthy HTTP metrics with the empty trace observations and missing-evidence entry; show the effective HOLD and saved policy reason.
    Say: “HTTP success and latency look healthy, but this investigation is missing the required trace-linked request observations. The dependency and retry cross-check is incomplete, so Decision Policy holds promotion until we restore evidence and investigate again.”
    Recover: select Healthy release, confirm the same active candidate, and investigate again. The scenario withholds evidence in that investigation; it does not stop or repair Jaeger. Human approval cannot override a missing prerequisite. A complete eligible Development investigation can produce GO; Production still requires approval.
    Attendee insight: absence of evidence is not evidence of safety. HOLD for missing information differs from NO-GO for an evidenced regression.

    Agent execution errors
    A failed workflow remains HOLD with an explicit Agent execution failed cue. Evidence explorer → Agent execution diagnostics shows safe error categories and exception types. Recoverable model failures can retry once within the original deadline and tool budget. If the retry fails, investigate again at the same active gate. Waiting for traffic or clearing a dependency fault does not repair model execution.
    Numerical reasoning and recovery
    Tools supply exact Java-computed comparisons: 7.8 ms is below 500 ms, and 58 requests meets the minimum 30. If an agent contradicts these checks, one correction pass uses the same frozen evidence within the original deadline and tool budget. Evidence explorer retains the original and corrected reports under Numerical consistency review. Passing thresholds alone never forces GO. After clearing a slowdown, let the affected requests leave the 60-second window before investigating recovery. At 50%, wait for fresh samples and investigate that stage.
    Human approval or rejection
    For an otherwise eligible Production GO, choose Approve promotion to authorize the current gate, or Decline promotion to record a human NO-GO. Argo aborts the candidate when it reads the rejection. Evidence explorer preserves the original GO recommendation and the presenter review. Both controls reject expired, superseded, or mismatched reviews. A missing-evidence HOLD or existing NO-GO has no pending approval to decline.

    PRODUCTION DESIGN / CONFERENCE DISCUSSION
    From a presenter click to an automatic investigation.
    Automate when reasoning starts. Keep evidence, policy, and rollout authority explicit.
    

    Design guidance — automatic investigations are not enabled in this demo.
    The current SPA starts agents only when you click Investigate. Production can use a server-side trigger at both 10% and 50%; automatic investigation does not imply automatic promotion.
    

    

    01 / CURRENT DEMO
    Manual investigation
    The presenter starts the four agents at each ready gate. Development permits an eligible GO; Production waits for human review.
    Benefits: predictable storytelling, deliberate fault timing, and fewer model calls.
    Tradeoffs: operator delay, repeated clicks after recovery, and the possibility of exhausting the analysis window while waiting for an operator.
    

    02 / SUGGESTED ADOPTION START
    Automatic investigation + human review
    A server-side coordinator starts reasoning when a gate has complete, fresh observations. A Production GO still waits for Approve or Decline.
    Benefits: no investigation click to miss; people retain the production authorization decision.
    Tradeoffs: durable work tracking, retry budgets, and approval freshness need explicit design. An approval wait still adds latency; the evidence freshness clock already runs while the agents work.
    

    03 / AFTER VALIDATION
    Automatic investigation + policy-authorized promotion
    For releases an organization classifies as suitable for unattended promotion, a versioned policy can accept an eligible GO automatically.
    Benefits: less operator wait and consistent stage handling.
    Tradeoffs: more responsibility rests on evidence quality, policy coverage, model evaluation, and recovery behavior. This demo's Production profile still requires human review.
    

    

    PROPOSED SERVER-SIDE FLOW
    How each automatic gate would work
    

    1. Observe an active analysis gate. A coordinator watches or reconciles the Rollout and AnalysisRun at 10%, then independently at 50%.
    2. Check readiness before reasoning. Require complete telemetry, enough observations collected for the current stage, and valid identity. The demo uses 30 requests per cohort; production thresholds need workload-specific validation.
    3. Claim one investigation attempt. Atomically record the gate identity in durable storage before dispatching a bounded worker. Repeated watch events or status polls return existing work.
    4. Freeze evidence and run four agents. Reuse the investigation workflow and Decision Policy; persist the evidence, tool reads, model/prompt/policy versions, result, and any human review.
    5. Serve the saved effective decision. Argo's five-second status poll reads GO, HOLD, or NO_GO. At 50%, require a new gate identity and fresh evidence; the 10% GO cannot authorize it.
    

    The five-second status poll must not become a five-second LLM invocation loop.
    

    Gate identity: cluster + namespace + Rollout UID + candidate pod-template hash + stable hash + step index + AnalysisRun UID. Track a bounded capture-attempt number for legitimate re-investigation at that gate. A version label such as v2 is insufficient.
    

    HOLD handling: collect changed evidence after recovery or missing telemetry returns. Retry an execution error only within its budget; do not keep rerolling the model on the same evidence until GO. An expired approval needs a new investigation and a new review. Human decline or NO_GO stops that candidate.
    

    Implementation choices in Quarkus and Argo
    Coordinator + existing Web status gate: reuse Quarkus Kubernetes Client watches, or Scheduler reconciliation, to discover ready gates. Dispatch work asynchronously and keep GET /api/analysis as a cheap read. Scheduler concurrentExecution=SKIP prevents overlap within one process; multiple replicas still need a durable claim or distributed coordination. Quartz with a database is another scheduling option; it does not remove the need for idempotency.
    Argo Job analysis provider: launch a bounded job per gate to submit an idempotent investigation and wait for its saved result. This makes execution visible as a Kubernetes job, with pod startup and lifecycle overhead. Job success requires completion with exit code zero: HOLD must keep waiting rather than exit successfully, and timeouts/failures must have an explicit fail-closed outcome.
    Idempotent Web POST option: Argo also supports POST measurements. A future ensure-investigation endpoint could enqueue once and return a saved status quickly. It needs a durable gate key, authentication, and duplicate-request handling. Repeated POST measurements must not dispatch repeated agents.
    These are proposed additions. The current POST /api/evaluate and in-memory DemoStore do not provide a durable automatic coordinator.
    

    

    FAULT INJECTION AND AUTOMATION
    Keep the experiment ahead of the investigator.
    In the current conference flow, wait for the 10% ready cue, inject the 25-second slowdown, wait until both cohorts show it, and then investigate. An automatic healthy investigation could otherwise produce GO and advance before the presenter injects the fault.
    1. Arm an explicitly authorized experiment. For staging or a controlled demo, mark the scenario as pending before an automatic investigation can start.
    2. Inject and confirm affected evidence. Wait for the intended shared slowdown in both cohorts and the required observations; then release the experiment precondition.
    3. Recover and reassess. After the fault is cleared or expires, collect a new recovery window before another bounded attempt. A new 50% gate still needs its own investigation.
    Normal production automation observes real conditions. It does not inject faults on every release. Any production resilience experiment needs separately scoped authorization, isolation, and recovery controls.
    

    HOW TO ADOPT THIS DESIGN
    Prove the evidence contract before expanding autonomy.
    Start with shadow evaluation
    Compare recommendations with operator decisions and real outcomes while independent safety checks remain blocking. Argo dry-run metrics can support observation without influencing rollout success. This demo has one governed analysis metric: preserve or add blocking checks before making that metric non-gating.
    Then automate investigation
    Add durable claims and results, bounded queues and model concurrency, cooldowns, cancellation on a superseded gate, and observable timeout outcomes. Keep Production human review while evaluating decision quality.
    Make unattended promotion a risk policy
    Define which changes qualify, evaluate false GO/HOLD/NO_GO outcomes, and expand gradually. Missing evidence, stale decisions, and exhausted budgets must never silently become permission.
    Replace demo shortcuts
    Persist work and audit records outside the control pod, use workload identity for automation and per-user RBAC for reviews, separate release-writing credentials from read-only investigators, and size observation windows and deadlines for the actual workload. A pod-local lock or browser session is not distributed coordination.
