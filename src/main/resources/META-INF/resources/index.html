    Decision Policy

    Fixed rules validate the agents’ recommendation before Argo can act.

    • At least 30 requests per revision and fresh evidence (120-second expiry).
    • Hold when required evidence is missing or limitations remain unresolved.
    • Enforce error and latency safety limits before GO.
    • Production promotion requires human approval (HITL).

    Human approval rechecks these rules; it cannot override missing or stale evidence or hard safety limits.

    CORE FLOW
    1. 1 / Establish the baselineLook for the green Rollout: Healthy badge, Stable v1, and No active canary. Use Reset demo to v1 when needed. A reset that creates a rollout still requires investigations at its analysis gates; once v1 is Healthy, reset again to clear the presentation.
    2. 2 / Release v2 through GitSelect Shared slowdown and candidate v2, then Release selected version through Git. Stay in Release progress. The 15s pause is warm-up before analysis, not a click deadline. The analysis allows 180 HTTP checks at 5s intervals (about 15 minutes).
    3. 3 / Inject the shared slowdownAt the 10% analysis gate, select Inject 25s shared slowdown. This adds 650 ms to inventory calls for 25 seconds. Allow affected requests to enter the observation window; Live console → Checkout pods can show their latency.
    4. 4 / Investigate explicitlyKeep Development / no approval for the core flow. Wait for the green Ready to investigate cue and at least 30 live requests in BOTH stable and canary. Select the single Investigate v2 at 10% action. Follow four LLM agents in Decision activity; Decision Policy determines the effective result. Customer degradation should withhold promotion with HOLD.
    5. 5 / Recover and advanceClear the fault or let it expire. Let affected observations drain from the 60-second window, then investigate again at 10%. After GO, watch Argo advance to 50%. Wait for the new ready cue and run a fresh investigation. Another GO allows full promotion.
    6. 6 / Expose the hidden retriesSelect Hidden retries, release v3 through Git, and investigate at its ready gate. Compare HTTP success and latency with increased inventory attempts. Inspect the recommendation, Decision Policy, and actual rollout outcome; NO-GO causes Argo to abort the candidate.
    7. 7 / Show the evidence and outcomeOpen Evidence explorer and export the decision record. Live console offers agent activity, Quarkus Java logs, and Argo controller logs. These SPA views keep the core story in one screen.
    Only release reconciliation and controller progression are automatic. Fault injection and each four-agent investigation remain presenter-triggered. If analysis finishes Inconclusive, request a fresh Git release/reset; running agents cannot restart that finished gate.
    EXTENDED FLOW
    Human-in-the-loop (HITL)
    1. 1 / Select Production / approvalUse a healthy candidate at an active gate with fresh samples. Run an investigation explicitly.
    2. 2 / Separate recommendation from authorityShow an eligible agent GO recommendation held as effective HOLD because Decision Policy requires approval.
    3. 3 / Approve with fresh evidenceSelect Approve promotion. Decision Policy rechecks eligibility, then Argo consumes the effective GO. A later Production gate needs a fresh investigation and approval.
    Decision Policy
    Implemented as deterministic Java/Quarkus rules in DecisionPolicy.java. Requires 30 requests per revision and fresh evidence; withholds GO for missing evidence or unresolved limitations; enforces error and latency limits; and requires eligible Production promotions to receive human approval. Approval cannot override these safeguards.
    Inspect uncertainty and telemetry
    Choose Extended in Demo mode to reveal Missing evidence. Demonstrate withholding promotion when required traces are absent. Follow an evidence trace ID in Jaeger, compare Prometheus signals, or inspect the paper-style Architecture diagrams. These are optional detail views.
